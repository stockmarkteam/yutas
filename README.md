# yutas

ひらがなを打って Shift を2回押すだけで、完成した文章に置き換わる、Mac 用の入力ツールです。

```
あしたのみーてぃんぐ15じ、じゃなくて16じにへんこうおねがい   ← 打つ（変換しない）
        ↓ Shift を2回
明日のミーティングを16時に変更お願いします。                 ← 置き換わる
```

変換キーを押して候補を選ぶ操作が要りません。打ち間違いも言い直しも、そのまま打ち進めれば AI が直します。声を出さないので、職場でもそのまま使えます。

> **現在の状態**: 社内で試している段階です。実際のアプリ上での清書は、まだ確かめきれていません。

## できること

| | |
|---|---|
| **どのアプリでも** | メール、チャット、メモ、ブラウザ。カーソルがある場所の文章がそのまま置き換わります |
| **変換せずに打てる** | ひらがなのまま打ち進めます。漢字・カタカナ・英数字への変換は AI がまとめて行います |
| **打ち間違いと言い直しを直す** | タイポや「〜じゃなくて」を Backspace で消さなくても、意図をくんで直します |
| **口調を整える** | 丁寧、カジュアル、敬語メールなど。アプリごとに変えられます（Slack はカジュアル、メールは敬語） |
| **社内の AI だけを使う** | Claude は社内の AI 基盤（Stockmark AX）を通して呼びます。Claude API には直接つなぎません |

## 使い方は 3 ステップ

1. 文字を入れたい場所をクリックする
2. 日本語入力をオンにして、**変換せずに**ひらがなを打つ
3. **Shift を2回**押す。1〜2 秒で清書された文章に置き換わります

清書している間は、画面の下に「清書中…」と小さく表示されます。

| やりたいこと | 操作 |
|---|---|
| 打った文章を清書する | ひらがなを打ち、変換せずに Shift を2回押す |
| 書いてある文章を清書する | 文章を選択して Shift を2回押す |
| 清書を取り消す | 清書の直後に、もう一度 Shift を2回押す |
| 清書を途中でやめる | 清書中に Esc を押す |

「2回押し」は、Shift だけを押して離す操作を 0.35 秒以内に2回です。Shift+文字のような普段の使い方には反応しません。清書中に打った文字は捨てられず、清書が終わったあとに順番どおり入ります。

## 打ったままが、そのまま使える文章になる

| 打った内容 | 置き換わる文章 |
|---|---|
| `あしたのみーてぃんぐ15じ、じゃなくて16じにへんこうおねがい` | 明日のミーティングを16時に変更お願いします。 |
| `しりょうかくにｎしました、もんだいないです` | 資料を確認しました。問題ありません。 |
| `きょうのてんきは？` | 今日の天気は？ |

- 言い直しは、言い直したあとの内容だけが残ります
- 打ち間違い（文字の抜け、重複、隣のキー）は直ります
- 内容は足しません。質問を打っても、答えずに質問文として清書します

## 名前や社内用語は、辞書に登録

人の名前や製品名は、読みだけでは正しい表記が決まりません。辞書に登録しておくと、必ずその表記になります。短い略記を長い言い回しに展開することもできます。

```
はしば      → 羽柴
くろーどこわーく → Claude Cowork
おつ        → お疲れ様です
```

メニューバーのアイコン ›「設定…」›「辞書」で登録します。「読み・略記」を入れて Enter を押すと「表記」に移り、もう一度 Enter で次の行に進みます。画面下の「試す」欄で、保存する前に結果を確かめられます。

## 設定はメニューバーから

yutas にはウィンドウがありません。画面右上のメニューバーに「あ」のアイコンが出ます。**Dock や Launchpad でアイコンを押しても画面は出ません。**メニューバーにアイコンがあれば、もう起動しています。

アイコン ›「設定…」で開く画面で、次のことを変えられます。「保存」を押すとすぐ反映され、再起動は要りません。

| タブ | 項目 | 内容 |
|---|---|---|
| 口調 | 既定の口調 | 清書するときの文体。「丁寧」「カジュアル」「敬語メール」「変換のみ」から選んで書き換えられます |
| 口調 | アプリ別の口調 | アプリごとの口調。アプリ名（`slack`、`google chrome`）で指定します |
| 口調 | 追加の指示 | 口調以外で、いつも守らせたいこと |
| 辞書 | 読み・略記 → 表記 | この読みが出てきたら、必ずこの表記にします |
| 一般 | 清書に使う AI | Claude（社内ゲートウェイ）か、ローカル LLM |
| 一般 | サインイン | 社内の AI 基盤へのサインインとサインアウト |
| 一般 | 清書のキー | Shift / Control（左右の指定可） |
| 一般 | ログイン項目 | ログイン時に yutas を起動します |

## はじめる準備は、最初の 1 回だけ

1. DMG を開き、yutas を「アプリケーション」フォルダへドラッグして起動する
2. 確認が出たら、**アクセシビリティ**を許可する（システム設定 › プライバシーとセキュリティ › アクセシビリティ で yutas をオン）。キー入力の検知と、清書した文章の貼り付けに使います
3. メニューバーのアイコン ›「設定…」›「一般」で「サインイン」を押す。ブラウザが開くので、会社の Google アカウントでサインインする。ブラウザに出るコードが、設定画面のコードと同じことを確かめてください

サインインは一度すれば続きます。期限が近づくと自動で更新されます。

## 打った内容は、決めた先にしか出ない

- **送り先は社内の AI 基盤だけ**: Claude で清書するとき、清書する文章・口調・辞書・追加の指示を、社内の Claude apps gateway（`https://ax.stockmark.co.jp`）にだけ送ります。推論は東京リージョンの Amazon Bedrock で行われます。Anthropic の API には送りません。送り先はアプリに固定してあり、設定では変えられません
- **モデルは Claude Haiku 5.5**: 速さを優先して固定しています
- **打鍵は残さない**: 打ったキーは、未確定の文字数を数えるためにメモリの上でだけ持ち、確定のたびに捨てます。ファイルには書きません
- **サインイン情報**: Mac のキーチェーンに保存します。設定ファイルやログには書きません
- **ログ**: 所要時間と成否だけを記録します。打った内容は記録しません
- **クリップボード**: 読み取りと貼り付けに一時的に使い、テキストは元に戻します。画像など、テキスト以外をコピーしていた場合は元に戻りません
- **Mac の外に出したくないとき**: 設定で「ローカル LLM」（Ollama、LM Studio など）を選ぶと、文章はその Mac の中だけで処理されます。精度と速さは、モデルと Mac の性能によります

## Shift を2回押しても清書されないとき

| 確かめるところ | どうする |
|---|---|
| メニューバーのアイコン | 「あ」のアイコンがなければ、yutas が起動していません |
| アクセシビリティ | 設定画面の上に案内が出ていたら、「システム設定を開く」から yutas をオンにする。一覧でオンなのに案内が消えないときは「許可をやり直す」を押す |
| サインイン | 設定画面の右上が「未サインイン」なら、「一般」タブでサインインする |
| 接続元 | 社内の AI 基盤は日本国内からしかつながりません。海外では使えません |
| 「入力を追跡できませんでした」と出る | ひらがなを打ったあとに、変換（スペース）や矢印キーを使うと清書できません。打ったら、そのまま Shift を2回押してください |
| 「IME がオフです」と出る | 日本語入力（ひらがな）に切り替えてから打ってください |
| 「利用上限に達しました」と出る | 社内の AI 基盤の月ごとの上限です。現在の使用量は https://ax.stockmark.co.jp/me で見られます |
| JetBrains の IDE | Shift の2回押しが「どこでも検索」と重なります。設定で清書のキーを右 Shift や Control に変えてください |

分からないこと・困ったことは AX まで。

## 使える Mac

| 項目 | 条件 |
|---|---|
| macOS | 12 以降 |
| 日本語入力 | ローマ字入力。かな入力には対応していません |
| キーボード | US 配列または JIS 配列（QWERTY）。Dvorak などには対応していません |
| ネットワーク | 日本国内から。Claude で清書する場合に必要です |

## 知っておいてほしい制限

- **打ったあとに変換やカーソル移動をすると清書できません**: スペース変換、矢印キー、Tab などを使うと、どこまでが打った文章か分からなくなるためです
- **日本語入力は、macOS 標準のものを前提にしています**: 確定の前に Control+J でひらがなに戻しています。Google 日本語入力などでは、キー設定によって動かないことがあります（未確認）
- **パスワード欄では反応しません**: macOS がキー入力を保護しているためです
- **選択なしで Shift を2回押すと、行全体が対象になるエディタがあります**: VS Code など、選択なしのコピーが行コピーになるアプリです
- **貼り付け（Command+V）ができないアプリでは動きません**
- **メモリ**: 本体は軽いですが、画面下の表示に使う WebView が 100MB 以上を使います

## 開発者向け

### ビルド

[Rust](https://rustup.rs/) と [Node.js](https://nodejs.org/) が要ります。

```bash
npm install
npm run build
```

次の 2 つができます。

- `src-tauri/target/release/bundle/macos/yutas.app`
- `src-tauri/target/release/bundle/yutas_<バージョン>_arm64.dmg`（配るのはこちら）

#### 署名と公証

`npm run build`（`scripts/build-mac.sh`）は、Developer ID で署名し、Apple の公証を受けます。資格情報は roku-log と同じものを、同じ変数名で使います。シェルの環境変数か、このフォルダの `.env`（コミットしません）に書きます。

| 変数 | 用途 |
|---|---|
| `ELECTROBUN_DEVELOPER_ID` | 署名に使う Developer ID の識別名（`Developer ID Application: 名前 (チームID)`） |
| `ELECTROBUN_APPLEID` | 公証に使う Apple ID |
| `ELECTROBUN_APPLEIDPASS` | App 用パスワード |
| `ELECTROBUN_TEAMID` | チーム ID |

roku-log の `.env` をそのまま使うなら、`ENV_FILE=../roku-log/.env npm run build` とします。

- `ELECTROBUN_DEVELOPER_ID` が無いときは、キーチェーンに 1 つだけある Developer ID の証明書を使います
- Apple ID の 3 つが揃っていないときは、**署名だけして公証はしません**。自分の Mac では動きますが、他の人に渡すと macOS が開くのを拒みます。ビルドの最後に `notarized: yes` と出ていることを確かめてから配ってください

署名した人（チーム）が同じなら、ビルドし直してもアクセシビリティの許可は引き継がれます。署名のしかたを変えた直後は、許可が外れたように見えることがあります。設定画面の案内の「許可をやり直す」を押すか、`tccutil reset Accessibility dev.yutas.app` を実行して、もう一度オンにしてください。

起動時に `--settings` を付けると、設定画面を開いた状態で始まります。

```bash
open src-tauri/target/release/bundle/macos/yutas.app --args --settings
```

### テスト

```bash
cd src-tauri
cargo test
```

ゲートウェイまわり（サインイン、トークンの更新、推論）のテストは、テストの中で立てた模擬サーバーを相手に動きます。実際のゲートウェイにはつなぎません。

`YUTAS_PROVIDER=mock` を設定して起動すると、AI を呼ばずに「【清書】」を頭に付けるだけのモックで、キー操作まわりの動きを確かめられます。

### 仕組み

macOS には、他のアプリの IME が持っている未確定の文字列を外から読む方法がありません。そこで次の手順を取っています。

1. イベントタップで打鍵を見て、ローマ字かな変換を自前で再現し、未確定の文字列が何文字あるかを把握する
2. Shift の2回押しを検知したら、ライブ変換で漢字になっている表示を Control+J でひらがなに戻し、Enter を送って確定する
3. 確定した文字数ぶんを Shift+← で選択し直し、コピーして読み取る
4. 読み取った文字列が、手順 1 で追跡した内容と一致するかを照合する。一致しなければ何もせず中断する
5. AI に送り、結果を貼り付けて選択範囲を置き換える。クリップボードは元の内容に戻す

IME 自体は置き換えません。普段使っている IME の上で動きます。

Claude の呼び出しは、社内の Claude apps gateway へのデバイスコードでのサインイン（ブラウザで会社のアカウントにサインインする方式）で得たトークンを使い、ゲートウェイの `/v1/messages` に送ります。

| ファイル | 役割 |
|---|---|
| `src-tauri/src/hook.rs` | 2回押しの検知、未確定文字列の追跡、清書中の打鍵の保留 |
| `src-tauri/src/keys.rs` | イベントタップ、キー送信、クリップボード、前面のアプリ、入力ソースの状態 |
| `src-tauri/src/vk.rs` | キーコード |
| `src-tauri/src/romaji.rs` | ローマ字かな変換の再現と、読み取り結果の照合 |
| `src-tauri/src/engine.rs` | 確定→読み取り→清書→置き換え→取り消しの流れ |
| `src-tauri/src/llm.rs` | プロンプトの組み立てと、Claude（ゲートウェイ経由）/ ローカル LLM の呼び出し |
| `src-tauri/src/gateway.rs` | Claude apps gateway へのサインインと、トークンの更新 |
| `src-tauri/src/settings.rs` | 設定の読み書き |
| `src-tauri/src/secrets.rs` | サインイン情報の保存（キーチェーン） |
| `src-tauri/src/autostart.rs` | ログイン時の自動起動 |
| `scripts/build-mac.sh` | ビルド、署名、公証、DMG の作成 |
| `src-tauri/src/pill.rs`, `ui/pill.html` | 画面下の状態表示 |
| `ui/settings.html` | 設定画面 |

### ファイルの場所

| | 場所 |
|---|---|
| 設定 | `~/Library/Application Support/yutas/config.json` |
| ログ | `~/Library/Logs/yutas/yutas.log` |
| 自動起動 | `~/Library/LaunchAgents/dev.yutas.app.plist` |

ログに打った内容が入るのは、環境変数 `YUTAS_DEBUG` を設定したときだけです。

### ローカル LLM を使う

1. ローカル LLM のサーバーを起動し、モデルを用意する。Ollama の例: `ollama pull gemma3:4b`
2. 設定の「一般」で「ローカル LLM」を選ぶ
3. エンドポイント URL を確かめる。既定は Ollama の `http://localhost:11434/v1`、LM Studio なら `http://localhost:1234/v1`
4. 「モデル一覧を取得」を押してモデルを選び、「保存」を押す

小さいモデルは同音異義語を間違えやすく、応答に数秒かかることがあります。答える前に思考するモデル（Qwen の思考モードなど）は、1 文の清書に十数秒以上かかることがあるので向きません。「試す」欄で実用になるか確かめてから使ってください。
